PARTE 1

O que é um WebService? (API)

Imagine o Garçom de um restaurante. O Cliente (Front-End) não vai à cozinha (Banco de Dados). Ele chama o Garçom (API), que busca a informação e a devolve no formato correto.

  • Agnóstico: Um jogo em Unreal (C++) consome a mesma API que um App em Kotlin.
  • Dados, não telas: O Back-End não devolve botões e cores, apenas dados brutos.
  • Reutilizável: A mesma API alimenta o Ranking do site, o Launcher e o Jogo.

PARTE 2

HTTP Status Codes (O Destino)

O Servidor responde não só com dados, mas com um número universal que indica o que rolou.

2xx Sucesso

200 OK (Deu bom)
201 Created (Criado com sucesso)

3xx Cache/Redirect

301 Moved Permanently
304 Not Modified (Usa o Cache local)

4xx Erro do Cliente

400 Bad Request (Faltou dado)
401 Unauthorized (Sem token)
404 Not Found (Jogador não existe)

5xx Erro do Servidor

500 Internal Server (O código quebrou)
503 Service Unavailable (Caiu)

PARTE 3

REST (A Regra de Ouro)

REST (Representational State Transfer) não é um código, é um estilo de arquitetura. APIs RESTful usam o HTTP de forma semântica.

✅ O Jeito RESTful (Certo)

Usar substantivos no plural e deixar a ação para o Verbo HTTP.

  • GET /guildas/15/membros
  • POST /jogadores
  • DELETE /inventario/item/99

❌ O Jeito RPC (Errado)

Colocar verbos e ações diretas na URL.

  • GET /pegarMembrosDaGuilda15
  • POST /criarNovoJogador
  • GET /deletarItem?id=99 (Destrutivo via GET!)
PARTE 4

O Grande Problema: A Língua

Se o nosso servidor Aetheria usa TypeScript, e o jogador está no celular usando Kotlin... Como eles enviam uma Guilda inteira pela internet?

Eles precisam de um idioma textual neutro.

❌ XML (O Passado)

<jogador>
  <nome>Faker</nome>
  <level>50</level>
</jogador>

Muito pesado. Repete tags sem parar.

✅ JSON (O Presente)

{
  "nome": "Faker",
  "level": 50
}

Leve, legível e nativo da Web.

PARTE 4

As Rígidas Regras do JSON

O JSON é rigoroso para que qualquer máquina do planeta consiga lê-lo sem travar.

  • Aspas Duplas: A chave TEM que ter aspas duplas. ("hp": 100).
  • Tipos Suportados: String, Number, Boolean, Null, Arrays [], Objetos {}.
  • Proibições: Sem funções. Sem comentários. Sem aspas simples. Sem `undefined`. Sem vírgula sobrando no final.

TS Objeto vs JSON

const ts = {
  nome: 'Ana',
  atacar: () => {}
}
{
  "nome": "Ana"
}
PARTE 4

Coleções (Arrays)

Ao fazer um GET /ranking, a API responde com uma Coleção de Objetos JSON. O array `[` abraça múltiplos `{ }`.

Geralmente, APIs modernas envelopam os dados em metadados como paginação e total de itens.

{
  "page": 1,
  "totalPages": 5,
  "data": [
    { "id": 1, "nick": "Faker", "elo": "Challenger" },
    { "id": 2, "nick": "Jukes", "elo": "Grandmaster" }
  ]
}
PARTE 4

Node.js: Serialização (O Embarque)

Como pegamos a Classe viva da memória e transformamos no texto JSON?

const textoJSON = JSON.stringify(guilda);

O stringify limpa métodos e garante aspas duplas. Prontinho para voar pela rede.

Como pegamos um pacote de texto da rede e trazemos de volta à vida?

try {
  const guilda = JSON.parse(textoJSON);
} catch(e) {
  console.log("Erro de Sintaxe. Arquivo corrompido!");
}

O parse é a operação mais rápida do V8, mas sempre precisa de Try/Catch.
